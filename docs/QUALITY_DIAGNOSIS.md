### 核心业务链路

1. 新建：爬楼决策 → 爬楼说明 → 位置/订单/客户 → 楼层门禁 → 现场附件 → 保存。
2. 查找：统计 / 搜索 / 状态筛选 → 列表大字楼层房号 → 现场媒体或详细信息。
3. 详情：完整字段 → 编辑 / 再来一单 / 复制摘要 / 删除。
4. 备份：zip 导出 → SAF 选择位置；导入合并/覆盖。
5. 更新：GitHub latest Release → SHA-256 → 系统安装器覆盖安装。
6. 快速输入：定位按钮获取坐标；剪贴板文字本地解析订单字段。

### 七个维度的结论

#### 1. 逻辑性

- 主干闭环：新建 → 保存 → 列表 → 现场/详情 → 编辑/删除 → 备份/更新均有测试或实测。
- 状态机：`TriState` 三态；表单校验位置必填、尾号 4 位、媒体 20 个上限；详情缺失记录显示返回态。
- 边界：空字段占位、空媒体、空剪贴板、无可识别订单、超长备注（200/300 截断）、大字体换行均已覆盖。
- 发现并修复：定位按钮因 `LaunchedEffect` 自取消而永远不执行；剪贴板异常读取可能让表单崩溃。
- 残余：删除无撤销、无回收站；无自动草稿保存。

#### 2. 稳定性与可靠性

- Room 写操作使用事务；备份导入使用事务；保存中禁止放弃，避免删掉刚入库媒体。
- 更新下载有 generation token，取消后回调不会重新弹层；`CancellationException` 不转成错误。
- 备份导入在复制/插入失败时清理新文件，提交成功后不再因清理/进度回调删除已引用媒体。
- 相机拍照/录像 setup 有异常兜底；启动清理超过 5 分钟的孤儿媒体。
- 并发/幂等：单 Activity + 单用户；保存按钮有 `saving` 锁；导入/导出有阻塞弹窗；更新下载有唯一 job。
- 残余：无自动重试策略（位置/更新需用户再点一次）；无全局崩溃兜底；备份导出到 SAF 失败可能留下部分文件。

#### 3. 安全性

- 组件面：仅 launcher Activity 导出；FileProvider `exported=false`，只暴露 `cache/updates/`。
- 网络：`usesCleartextTraffic=false`；更新 URL 只接受 GitHub 域名，最终重定向也校验；`.sha256` 强制校验；APK 250MB 上限。
- 注入：Room 全部参数绑定；筛选值来自枚举；无拼接 SQL。
- Web 风险：无 WebView、无服务端、无 HTML 注入面；XSS/CSRF/越权/RBAC 对本项目 N/A（本地单用户应用）。
- 数据：`allowBackup=false` + backup rules 排除全部目录；媒体在应用私有目录；日志不含客户数据。
- 隐私：剪贴板只在用户点击时读取，本地正则解析、不写日志、不联网、无新增权限；导出备份未加密，已在 UI 和文档提示。
- 发现并修复：剪贴板 `coerceToText` 异常未捕获可能崩溃；已加兜底。
- 残余：备份 zip 明文；无应用锁；无证书 pinning；更新信任 GitHub TLS + Android 同签名安装。

#### 4. 性能与资源

- Room `@Relation` 是批量关系查询，不是逐条 N+1；`createdAt` 有索引。
- Coil 按控件约束采样；视频缩略图在导入时生成；列表不加载视频文件本身。
- 风险：列表/备份一次性读取所有记录及附件，没有分页或归档；大量记录（数千条、每条 20 附件）时内存和首屏时间会上升。
- 风险：图片在列表中没有预生成缩略图，依赖 Coil 采样；极端大图仍可能增加解码成本。
- 未做正式 Macrobenchmark/内存泄漏探针；当前结论来自代码审查和实际运行，不是性能基线报告。

#### 5. 兼容性与前端边界

- API 35：全量 18 项仪器化。
- API 26：核心建记录与剪贴板填入通过，验证 minSdk 24 附近的主要路径。

- 无统一 Error Boundary/崩溃页；深色/1.3×/横屏已实际截图检查，TalkBack 语义仅做了主要控件标注。

#### 6. 自动化测试覆盖

- 核心缺口：没有 API 24 真机矩阵、没有网络故障注入、没有 Macrobenchmark、没有崩溃注入/恢复测试、没有 App 锁场景（功能未实现）。

## 项目想法与路线图

**产品差异化**：楼记不应该变成“另一个笔记 App”，而应成为“到楼下 10 秒内能做完决定”的私人楼道台账。核心亮点是：

1. **输入极快**：剪贴板识别已落地；下一步是订单截图 OCR + 最近位置/模板复用。
2. **读得极快**：大号楼层房号、状态印章、现场缩略图已经形成稳定视觉语言；继续保护“楼层第一眼”。
3. **私密可信**：本地存储、无账号；补应用锁和加密备份后，隐私承诺才完整。
4. **可恢复**：删除撤销/回收站、加密备份、导入前预览，降低骑手误操作成本。

**架构演进建议**：

- 将 `data` 层按 `record / media / backup / update` 拆分 repository 接口，便于为 OCR、加密备份和分页增加适配器。
- 列表引入 Paging 3 或按时间窗口查询；媒体缩略图统一生成管线。
- 把“输入识别”做成可测试的纯 Kotlin `OrderTextParser`（已开始），后续 OCR 只负责产出文本，解析与置信度逻辑复用。
- 可观测性坚持本地优先：本地诊断日志 + 用户主动导出，不默认上传客户数据。

**建议路线图**：

- **下一版（P1）**：应用锁 + 加密备份 + OCR 原型；补 API 24/25 真机冒烟。
- **再下一版（P1/P2）**：分页/归档、删除撤销/回收站、统计页、批量操作。
- **持续**：恢复 CI 自动门禁；每版保留 Lint/单元/仪器化/Mimosa/覆盖安装证据；把性能基线（首屏、内存、DB 查询）纳入发布检查。

## 结论

v1.4.0 在当前范围内通过静态检查、31 个单元测试、API 35 全量 20 个仪器化测试、API 26 核心兼容性测试、Mimosa 静态扫描、应用内更新和 release 冒烟。当前没有已知 P0 阻断；应用锁、归档与排序已完成，P1 剩余集中在加密备份、OCR、分页与 CI/可观测性。上述缺口没有被本轮“假修”或隐藏，均作为下一阶段明确路线图保留。
